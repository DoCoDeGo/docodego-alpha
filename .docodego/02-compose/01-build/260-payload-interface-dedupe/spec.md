# 260-payload-interface-dedupe

## intent

Enhancement 9 — the one quiet rot in the tree. The payload's types are
declared twice: bundle.ts holds the real `Payload` and
`SkillIndexEntry`, and hand-copies both into the template string that
generates payload.ts — two declarations synced by hand, no gate
watching. Every payload shape change (the auto-add field was the
latest) edits both copies and prays. The fix moves the declarations to
their natural home — `types.ts`, the shared-vocabulary module — bundle
imports them, the generated payload imports and re-exports them, and
the compiler becomes the gate: one declaration means any drift is a
type error, not a silent fork.

## scope

In: `SkillIndexEntry` and `Payload` declared once in
`apps/cli/src/types.ts`; `scripts/bundle.ts` imports them and drops
both its real declarations and the hand-copied block in the emitted
template; the generated `payload.ts` imports the types from
`../types.ts` and re-exports them (its consumers in `bundled/index.ts`
keep importing from payload.ts, unchanged); the payload is regenerated
(bytes identical apart from the header); conformance facts pin the
law — the string `interface Payload` appears only in types.ts, and the
generated payload imports the shared types. Out: touching the payload
FILE manifest (the boundary contract — 51 rows, unchanged);
VocabularyPack (already single, in record/vocabulary.ts); any payload
content change (specVersion stays 14 — the type move is not a record
migration).

## acceptance

- AC1 — the interfaces are declared exactly once: types.ts holds
  `SkillIndexEntry` and `Payload`; bundle.ts and payload.ts hold no
  `interface Payload` / `interface SkillIndexEntry` declaration text —
  proven by a conformance fact over the three files.
- AC2 — the generated payload.ts imports the types from ../types.ts
  and re-exports them, and its consumers are untouched — conformance
  fact + `bundled/index.ts` unchanged.
- AC3 — the regenerated payload's DATA is byte-identical to the old
  (same files, hashes, specVersion 14): `bundle --verify` clean, and
  the bundle's own shape checks green.
- AC4 — tsc green (the compiler now watches the single declaration),
  conformance green, canon lint/verify green.

## threats

- The generated file drifts from its generator — impossible to
  reproduce: the payload is regenerated by the (changed) bundle script
  in the same commit; `bundle --verify` proves the data unchanged.
- The type move breaking the embed at runtime — types are erased; the
  emitted file's runtime exports (PAYLOAD) are untouched.
- Accidental payload content change riding the regeneration — the
  manifest rows and hashes are recomputed from the same live folders;
  `bundle --verify` + the drift gates would name any difference.
