# the inventory — every artifact family, its first use, its second

The founder's cycle-6 directive, second message: dual use as
structural practice. An artifact family's second use is real only if
it names an audience — a person who was not in the room, reading
cold. Families whose second use is honestly none yet are recorded as
such; forcing one would be the word game the spec's threat names.

| family | primary use (first audience) | declared second use | second audience |
|---|---|---|---|
| conformance fixtures (`apps/cli/src/conformance.ts`) | prove the engine does what the laws say (the suite, 381 green) | the published demo — "what docodego enforces, shown" (`docs/fixtures-demo/`, shipped this unit) | a stranger evaluating adoption |
| spec-tree law (`spec/`) | govern what the engine must do (enforced-by map, amendments) | the published site — `canon publish --site` renders versioned law, llms.txt, a verification badge | a cold reader of the standard (human or agent) |
| proofs (`**/proofs.md`) | bind acceptance criteria to evidence at deliver (G4) | tutorials — each proof teaches how to verify a claim without trusting the author | a contributor verifying cold |
| explain pages (`apps/cli/src/passes/explain.ts`) | fix every refusal at the terminal (`docodego explain DG-U113`) | the plain-word law glossary — every code page states meaning, law, fix; `docs/diagnostics.md` is generated from them | the blocked operator, then the curious reader |
| demo bundles (`03-demonstrate/demo/*/how-to-run.md`) | the L5 launch proof — the show exists | ready-made how-tos — the fastest path from clone to seeing it work | a stranger wanting to see, not read |
| the record layer (`.docodego/`) | the studio's own build record (this repository is the dogfood) | the worked example — a full method run, readable clone-to-present, is the method's best argument | an evaluating adopter |
| help bodies (`apps/cli/src/cli/help.ts`) | the per-command contract at the terminal (`--help`) | inline teaching of the law behind each command (exit codes, refusal codes, why) | the operator at the moment of blockage |
| migration teach text (`apps/cli/src/versioning/migrations.ts`) | move old records forward without losing their words | the annotated changelog — each hop's notes say why the contract moved | the upgrader auditing what changed |
| vocabulary packs (`apps/cli/src/bundled/`) | an organization's dialect planted at init | the contract demonstration — words change, the record contract does not (v5's living proof) | the skeptic who fears lock-in |
| skills shelf (`.agents/skills/`) | agent how-tos for this repository's work | human onboarding — each skill is a readable manual for a phase | the new contributor |
| generated command docs (`docs/commands/`) | reference for every command, regenerated from the help registry | the cold intake — the same pages serve an agent reading the repo with no human guide | an agent reading cold |
| engine code (`apps/cli/src`, `apps/spec/src`) | the product | **none yet** — the refusal messages teach, but the source itself has no declared second reader; honest gap, revisit when an audience names itself | — |

The rule this inventory plants (staged for AGENTS.md, see
`teach-staged.md`): before delivery, ask whether what you built
teaches someone who was not in the room. Name the second audience or
record honestly that the family has none.
