# Contributing

docodego eats its own food: contributions run through the same loop the CLI
imposes on the repos it plants. If a change to the CLI cannot pass its own
gates, that is a bug in the gates — fix that first.

## Setup

- Node >= 22.6 (no flags needed at runtime; the build uses
  `--experimental-strip-types`, default-on in 23+)
- bun (only for the compiled binary target)
- `npm install` at the repo root (workspaces; typecheck and build resolve
  the toolchain from it)

## The loop (every change)

1. **Name it.** `docodego new <unit> --type unit` (or graduate a
   `docodego sketch`). One delivery unit is one commit.
2. **Write the spec, score it.** `docodego score <unit>` — the breakdown
   lands in the unit's score.md; lazy placeholder sections earn nothing by
   construction.
3. **Grill it.** `docodego grill <unit>` — answer honestly; failed rounds
   stay recorded as evidence, which is the point.
4. **Implement, and keep the proof.** proofs.md lists evidence-of-running
   paths that exist on disk (test output, built artifact, transcript).
5. **Deliver.** `docodego deliver <unit>` — G1 spec complete, G2 score ≥ 60,
   G3 grill pass, G4 a proof that exists. Nothing lands without green gates
   and the tracker line they append.

## The build gates (what must be green before you push)

```
npm run build         # bundle -> bump guard -> drift verify -> typecheck
                      #   -> conformance -> smoke (through built artifacts)
npm run docs:verify   # generated docs match the help/explain registries
```

Conformance is the law's test suite — every planted promise in AGENTS.md and
every exit code in the help pages is a check. If you add a promise, add a
check.

**Versioning law: hashes detect, humans declare.** Any change to a bundled
record file (`AGENTS.md`, anything under `.docodego/` or `.agents/`) forces
the declared `recordVersion` (in `.docodego/.standard/manifest.json`) to
cover the change — the bump guard fails the build otherwise, and an
under-bump is found by CI, not by users. CLI-only changes bump the package
version; strict semver, no shortcuts. Record migrations are ordered,
version-keyed, create-only, and never consolidated.

## Repository law

- **Conventional Commits**, lowercase: `type(scope): summary` — one delivery
  unit per commit.
- **Append-only records.** Superseded text is struck, quoted, or archived —
  never deleted. The trail of what was thought must replay.
- **No AI attribution anywhere** — no co-author trailers, no "generated by".
- **Plain English** in user-facing text; decode jargon on first use.
- **Zero runtime dependencies; strict TypeScript; the compiler-passes
  shape**: parse once → pure passes → emit. No command re-parses, no pass
  emits, no emit decides.
- **Claims link to evidence.** A claim without a path to its file is a
  wish.
- **The generated docs are law-adjacent:** edit `src/cli/help.ts` and
  `src/passes/explain.ts`, then run `npm run docs` — never edit
  `docs/commands/*.md` or `docs/diagnostics.md` by hand; `docs:verify`
  exists precisely to catch that.

## Where to start

The improvement backlog lives in the record (`.docodego/01-document/`).
Items marked open there are fair game; anything touching mission, naming,
money, or taste is a founder call — propose, don't decide.
