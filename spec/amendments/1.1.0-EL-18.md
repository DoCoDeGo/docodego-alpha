# Amendment EL-18 → 1.1.0

*An amendment to Evidence is a path (laws/18-evidence-is-a-path.md). It changes nothing
by itself: the law file, the version stamp, and the log move only when
this amendment is signed and accepted.*

## What changed

The law's "The law" section gains five proof semantics as normative
additions; the "Conformance" section is rewritten to name only what is
mechanized today (its current last line — "Direction: lint resolves
every evidence path in every record file" — names a direction, not a
check, and a conformance section that aspires is a claim without a
path; that direction is superseded, its landed parts named in the new
conformance text, and the replacement direction — reproduction
checking — named as not yet built). No statute words move; no other
law's meaning changes; severity stays veto, and no tool's own severity
changes — the veto ranks the law, the mechanics keep their own
strengths (warning for narration, error for no-resolvable, refusal for
drift). This draft is independent of the status-rails new-law draft in
the same batch: separate files, separate sign-offs; whichever is
accepted flips with the version bump, the other stays draft. The
proposed law text in full:

> ## The law
>
> Every claim on the trail points at its evidence — a file that holds it. A claim with no
> evidence is marked as assumed, or it is not written. "Records before claims": if the record
> does not exist, write it first.
>
> A proof — the evidence a delivered claim cites — carries five semantics:
>
> 1. **A proof is a path that resolves** — resolvable by the record's own
>    reader (the mechanics name the roots). No path, no proof. A citation
>    that names no readable file is decoration, not evidence.
> 2. **A proof is reproducible.** It holds what ran and what came out,
>    enough that a stranger — a reader with no context beyond the record,
>    human or agent — could re-run it and reach the same output. "It
>    passed" is a claim; the captured output is the proof.
> 3. **Failure is evidence.** A run that failed, recorded with the gap
>    named, is an honest proof of state — never hidden. A record that
>    shows only green runs is claiming a world with no failures in it,
>    which no real project inhabits.
> 4. **Narration is not claim.** Proof citations that name paths which
>    never existed (examples, schema identifiers, prose references) are
>    narration: a warning, honest history kept, no author marker required.
>    But a proofs file in which *no* cited path resolves has no evidence
>    at all — that is the error.
> 5. **Guards baseline the last delivered state.** Drift guards compare
>    the tree to the last delivered index: inside a delivery unit,
>    iterating is free; after delivery, the guards that baseline the
>    state refuse the drift. Done means the bytes matched when it
>    counted.
>

> *(unchanged)*

>

## Why

This session's own tooling proved the five semantics out before the law
said them: the retire gate refused a unit whose proofs named no
resolvable path while keeping narration as prose (4 and the error half
of 1); conformance proofs captured full command output so a stranger
can re-run them (2); the pre-commit bundle-drift report was recorded as
honest expected-red rather than suppressed (3); and the drift guards
constrained iteration inside the unit while refusing it after delivery
(5). Law that trails what the tools already enforce is the safe
direction of lag — but an unamended law invites a second tool to
enforce something else. The conformance line's unfinished direction is
repaired at the same time: conformance sections name what checks exist,
and futures move to "Direction", visibly not yet built.

## What risk it answers

The risk that "proof" drifts into whatever each tool happens to check —
five tools, five private meanings, and the record's central claim
("evidence is a path") eroded by divergence. Naming the semantics in
the law pins the shared contract: every current enforcement site (the
check pass, the retire gate, canon verify, the drift guards) and every
future one derives from one text. The EL-30 risk statement: without
this amendment, a proof that is a dead path, an unverifiable assertion,
or a suppressed failure satisfies one tool while betraying the record's
promise to its reader.

## Grilling (non-author, 2026-11-08)

Twelve questions from a reader who did not write the amendment, answered
on the record; revisions applied where an answer exposed a weakness, and
listed below the questions.

1. Who re-runs a "reproducible" proof, and when? If nothing mechanizes
   reproduction, why is semantic 2 normative rather than aspirational?
   — The duty binds writers now (capture output, name the gap);
   mechanized re-running is named under Direction, not pretended as a
   check. Normative-but-detection-today is the same split the amendment
   itself applies to the old conformance line.
2. What stops an author marking every dead path "narration"? Where is
   the line drawn mechanically? — There is nothing to declare: the
   tool counts. Some resolving path in the file = alive, the rest warn;
   none resolving = the error. Revision: semantic 4 now says "no author
   marker required".
3. Semantic 5 says drift "refuses" — refuses what, where? — The guards
   that baseline the state: bundle verify, canon diff/doctor, and the
   deliver gate's live-proof requirement. Revision: semantic 5 now says
   "the guards that baseline the state refuse the drift" instead of an
   unattributed "drift refuses".
4. Does any existing check change behavior under this amendment? — No.
   The mechanics shipped in the units that built them; the law records
   the shared contract. The Why section states this.
5. Does failure-is-evidence obligate recording every failure? — No:
   "recorded" limits the duty — a recorded failure is evidence, never
   hidden; the loop's weighting governs how much gets recorded.
6. The rewrite deletes the old "Direction: lint resolves every evidence
   path" — what happens to that future work? — It is superseded: its
   landed parts are named in the new conformance text; the replacement
   direction is named as not yet built. Revision: the supersession is
   now stated explicitly in What changed.
7. Why five? Is the enumeration stable under a future sixth? — Numbered
   for citation; additions append (6, 7, …) — the numbering never
   renumbers, by the append law.
8. "Resolves" — where? The three-root rule is CLI mechanics; does the
   law pin the roots? — The law pins the duty (resolvable by the
   record's reader); the roots stay mechanics. Revision: semantic 1 now
   says "resolvable by the record's own reader (the mechanics name the
   roots)".
9. Is an agent a valid "stranger" for reproduction? — Yes, and it is
   the primary one: the record layer is agent-operated by design.
   Revision: semantic 2 now defines the stranger explicitly.
10. Five semantics at veto — does a missing narration warning now veto
    a delivery? — No tool severity changes; the veto ranks the law.
    Revision: the severity note is now stated in What changed.
11. Why law at all, if the tools already enforce it — isn't that two
    places to drift? — Tools enforcing private policy is the drift; the
    law is the canon the tools' enforced-by lines cite, and canon
    verify checks those citations.
12. Semantic 4 calls dead paths "honest history" — a path that never
    existed is fiction, not history. Mechanically? — The tool does not
    distinguish, and the law does not claim it does: the warning means
    "not evidence, kept"; the all-dead error catches prooflessness.

Revisions applied: 2, 3, 6, 8, 9, 10 — each visible in the text above.
