# docs — read in this order

The CLI's working documentation. Numbered law lives in `spec/`; this folder
holds the guides.

1. `getting-started.md` — install, init, first unit
2. `architecture.md` — how the CLI is built
3. `record-format.md` — the record layer's grammar
4. `versioning.md` — the three version axes and the migration ladder
5. `commands/` — one page per command
6. `skills.md`, `vocabulary-packs.md`, `diagnostics.md`, `distribution.md` — reference

Evergreen reference has no sequence — number it and you fake an order that
does not exist. Dated audits live in `audits/` with date-LEADING names so
they sort by time (`2026-11-08-cli-law-audit.md`), newest first when listed
in reverse. Unit folders in the record carry their build order as `NNN-`
prefixes — names carry order (see AGENTS.md).
